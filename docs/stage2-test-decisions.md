# Stage 2 test-design decisions (tests-only revision)

This document records acceptance-test decisions only. It does not authorize production implementation or alter the frozen v2.9 matrix.

- **Determinism:** constructors will accept injected `sleep`, `jitter`, `now_ms`, and `http_client`; tests will not monkeypatch global time/sleep functions.
- **Sleep budget:** abort before sleeping when `total_slept + next_wait > 30`; exactly 30 seconds is allowed.
- **Timeouts:** `ConnectError` and `ConnectTimeout` are connect failures and may trigger host fallback only before the first successful server-time call. `ReadTimeout`, `WriteTimeout`, and `PoolTimeout` retry on the same host.
- **Cooldown file:** JSON shape is `{"until_ms": int, "reason": str}` and is global across allowed hosts. An active cooldown blocks all network I/O, including the time endpoint. Missing, corrupt, non-integer, or negative values fail closed.
- **Finality:** the client sends `endTime = effective_end - 1`. If upstream still returns any candle with `close_time_ms >= B`, abort; never silently drop it. The independent vectors live under `tests/fixtures/vectors/`.
- **Conflict comparison:** numeric `Decimal` equality for prices, base volume, and quote volume; integer equality for close time and trade count.
- **Exception contracts:** `EmptyEffectiveRangeError` for an effective end not greater than requested start; `NaiveDatetimeError` for naive input datetimes; `NonFinalCandleError` when upstream returns a non-final candle; `CorruptCooldownError` for invalid cooldown persistence. Tests assert type and diagnostic message.
- **Red-reason gate:** a failure is an expected red only when JUnit traceback includes `NotImplementedError` raised from `src/trading_app/`. Test-body placeholders, assertion failures, skips, collection errors, and unexpected passes are rejected. Passing tooling/CI/hygiene rows are explicitly allowlisted in `tools/red_reason_gate.py`.
- **Provenance:** the public baseline `a88a843` has tree `408a6a42…`; the local bundle's original commit identity is `de1bd38…` and is not present in public history. The revised commit message records that gap. Any push of original history is a separate, optional branch operation.

Any test expectation that conflicts with `matrix.yaml` requires a new spec version and reviewer sign-off; no frozen matrix or frozen tooling file is changed by this revision.

## Stage B2 decisions (client request engine)
- `cooldown_path=None` keeps cooldown in memory per client; production wiring must pass `data/binance_cooldown.json` so cooldown is global across processes.
- `now_ms` is used only for cooldown timestamps; finality never reads the local clock (server time or abort).
- Sleep budget (30s) and host lock are per fetch; the fetch owner calls `begin_fetch()`. `get_server_time` alone does not reset them.
- Connect/DNS failure before the first successful `/api/v3/time` switches once to the fallback host (counts as an attempt, no sleep). Afterwards connect failures are ordinary retryable transient errors on the locked host.
- Unparsable or non-integer `Retry-After` is treated as absent (exponential backoff). Only integer seconds are honored.
- A 429 whose backoff (no `Retry-After`) would exceed the sleep budget trips the budget cooldown (600s minimum). Non-429 retryable errors that would exceed the budget abort without cooldown.
- Out-of-range injected jitter is a programming error (`ValueError`), never silently clamped.
- Unknown transport errors (e.g. `ReadError`) are not retried.
- Two Stage-2 tests were defective and corrected in Stage B2: `test_retry_after_cap_and_no_jitter[429]` supplied one response while expecting four requests; `tests/unit/test_time_snapshot.py::test_no_local_clock_fallback` called the real network with no assertion (now hermetic). `tests/integration/test_time_snapshot.py` had the same real-network defect; it was rewritten hermetically in Stage B2 and stays red (stub) until Stage C implements the klines download.
- Cooldown is re-checked before every HTTP attempt (including retries after a sleep), so a cooldown written by another process while this client sleeps stops the next request.
- Cooldown updates use `extend_cooldown`: one exclusive file lock (sidecar `<name>.lock`) around read-compare-write, so the longest deadline always survives concurrent writers; the atomic temp-file replace is kept for crash safety.
- Evidence note: the mutation experiments for B2 were run locally by the implementer; CI does not run a mutation suite yet (planned for the final gate).

## Stage C decisions (klines download, security tests)
- `get_historical_klines` returns the raw Binance rows (lists) exactly as received, after validation; the service layer converts them. Keyword-only arguments.
- Order of operations: input validation (naive, alignment, order, symbol, timeframe) before any network call -> `begin_fetch()` -> one server-time snapshot S -> configured-lag check -> effective end -> empty-range error -> pagination.
- A missing `finality_lag_ms` fails the fetch with `BinanceClientError` after the server-time snapshot (as `test_finality_lag_has_no_default` requires). `finality_lag_ms=0` is valid by design (`lag_min_ms: 0`) and is used only by offline tests; any live run needs the lag approved after OBS-02.
- Pagination continues until the cursor reaches the effective end (a short page is not a terminator). An empty page stops paging, and the result is ALWAYS validated: an empty response for a non-empty effective range raises `DataValidationError` (`EMPTY_RESULT`); an empty page after data fails with `UNEXPECTED_END`. (Reviewer finding C1, preferred fail-closed default. Several Stage-2 tests had used `[]` as an incidental payload while asserting only the `endTime` clamp; they now supply real rows. If a legitimately empty range must be supported later, that needs an explicit spec change and a way for callers to distinguish it.)
- Non-final rows (`close_time_ms >= S - L`) raise `NonFinalCandleError` before structural validation; they are never dropped silently.
- Existing tests corrected in Stage C: tests that relied on an implicit zero lag now pass `finality_lag_ms=0`; `test_b_not_final_vectors_shrink_to_explicit_empty_range` now uses each vector's own `L_ms` (the 60s-lag cases were previously never exercised); LIVE-01/03 fake payloads were empty lists while asserting 12 and 1152 rows, so they now generate real rows. These remain offline stand-ins: the matrix still requires genuine live evidence for LIVE-01..04, which is a separate gate.
- Eight security tests (M1-04 x3, M1-16, TRIP-01/02, LOG-01/02) were hollow placeholders that called `get_historical_klines()` with no arguments and asserted nothing. They are replaced by real tests plus `tools/tripwire.py` (AST scan of `src/` and `scripts/`; `tests/` exempt; exact scanned-file count printed) and a client logging policy: only fixed labels, counts and status codes; never URLs, headers, params or exception text; transport errors are raised outside the `except` block so neither `__cause__` nor `__context__` carries the original exception text.
- Not covered yet: storage, repository conflicts, transactions, config, CLI/service wiring (Stage D); evidence, mutation runner, coverage gates and `pip-audit` (final gate).
- Review round on Stage C (C1-C4): empty responses are rejected (C1); the tripwire now detects aliased imports, attribute references, `getattr` string calls and the `/papi/` family (C2); cooldown persistence and corrupt-cooldown errors carry only fixed text or an exception type name, raised outside `except` blocks (C3); LOG-02 now injects an `httpx.HTTPStatusError` carrying a poisoned URL from the HTTP client itself (C4).

## Stage D1 decisions (settings, repository)
- Settings: no secret fields; unknown env vars (e.g. `API_KEY`) are ignored; symbols are upper-cased and de-duplicated; timeframes must be in the validator set (5m, 15m, 1h, 4h); `binance_base_url` must pass the host allowlist; `finality_lag_ms` has no default (None), 0 is valid; `max_candles_per_fetch` defaults to 100000 (pinned to the frozen YAML by a test). `pydantic-settings` lower bound raised to 2.7 (needed for `NoDecode`).
- Repository: Decimals are stored as `format(d, "f")` strings and compared numerically (100.10 == 100.1); conflict fields are close_time, OHLC, volume, quote_volume, trade_count (created_at excluded); a differing existing row, or conflicting duplicates inside one batch, raise `CandleConflictError` and roll the whole batch back; nothing is ever overwritten. Floats, bools, NaN/Infinity, naive datetimes, bad counts are rejected before any transaction starts.
- Transactions: one `BEGIN IMMEDIATE` per insert, taken only after validation (the connection runs in manual-transaction mode). Oversize fetches raise `TooManyCandlesError` before any engine use.
- SQLite: every new connection sets `journal_mode=WAL` (file databases) and `busy_timeout`; the parent directory is created before connecting. The frozen spec says only "the required busy timeout" without a value: **10000 ms was chosen** (deliberately not SQLite's own 5000 ms default, so the test can prove the setting is applied). Reviewer confirmation requested.
- Hollow-test ratchet: 18 acceptance tests contain no assertion at all (they call production code with no arguments). `tests/hollow_allowlist.txt` lists them; `tests/tools/test_no_hollow_tests.py` fails on any NEW assertion-free test and forces the list to shrink as they are replaced; in implementation-stage mode the red-reason gate tolerates (and counts) listed placeholders that fail. **The list must be empty at the final gate.** Tests replaced in D1: M1-02/03 (config), M1-07/08/13 (repository), R5-01/03 (pragmas), TX-03 (max candles).
- Review round on D1 (hollow-test ratchet hardening): the scanner (`tools/hollow_scan.py`) is AST-based, so comments, strings, `assert True` and `assert 1` do not count as checks; `assert_*` helper calls and `pytest.raises/fail/warns` do. The allowlist must be a subset of the pinned original list in `tests/tools/test_no_hollow_tests.py` (adding an entry is a visible code change), a missing or malformed allowlist fails closed, and a new `--final-gate` mode of `tools/red_reason_gate.py` requires pytest exit 0, zero failures/skips/errors, no hollow tests anywhere, and an EMPTY allowlist, regardless of any tolerance. It cannot be combined with `--implementation-stage`. One legitimate test (`test_empty_rows_without_expectations_have_no_issues`) was wrongly listed before and is now recognized as real (it relies on `assert_valid_klines`). Superficial-but-nonempty assertions are still possible and remain a review concern.
- Additional conflict coverage: every failure mode (existing-row conflict last, in-batch conflict after valid entries, invalid field after a valid entry) leaves the persisted state byte-for-byte unchanged.

## Stage D2a decisions (download service, audit, transaction shape)
- `MarketDataService.download_and_store` validates the allowlists and datetimes first; those rejections raise `ValueError` with **no** network call and **no** audit row (no fetch began). Every failure after that is audited.
- Order: network + finality + validation + conversion + hashing, then ONE `BEGIN IMMEDIATE` transaction saves candles and the success audit row together; any failure rolls both back. A separate short transaction then records a failure row; if that write fails it is only logged and the original exception is re-raised.
- `data_fetches` (one row per attempt): `schema_version` (1), symbol, timeframe, requested/effective start+end, `server_time_ms`, `finality_lag_ms`, `host`, `row_count` (rows fetched and fully VERIFIED, NOT only newly inserted. "Verified" means the client's checks AND the service's own conversion both passed. A FAILURE row carries the same count whenever the failure happens after verification, e.g. a hashing failure, a conflict or a failure after the write began, and 0 when it happens before, including rows that came back but could not be converted; conversion errors become `DataValidationError` with code `MALFORMED_ROW` and no row values), `dataset_sha256`, `status`, `error_class`, `error_text`, `fetched_at_ms` (injected audit clock; never used for finality). Fields unknown at failure time are NULL.
- Failure text is a fixed vocabulary derived from the exception CLASS (plus status codes, validation issue codes and conflicting field names); it never echoes the exception message. The repository also rejects unsafe audit text (defence in depth). The client exposes `last_fetch` (server time, lag, effective range, host).
- Test infrastructure: `tests/fixtures/service_env.py` records one timeline of network requests, SQLAlchemy events and SQLite's own statement trace; the order assertions (TX-01/02/09, AUDIT-02) read that timeline.
- Equivalent mutant accepted: removing the explicit `rollback()` is unobservable because closing the connection rolls back; the tests prove a ROLLBACK statement is executed before the failure-audit transaction.
- `tools/tripwire.py` has one explicit string-finding exemption: `src/trading_app/data/audit.py` (a secret-word denylist). HTTP-method and network-API findings still apply to it.

## Stage D2b decisions (concurrency, legacy scan)
- Concurrency tests launch real subprocesses (`tests/fixtures/concurrency_worker.py`, `process_runner.py`) against a shared SQLite file with a file-based start barrier; the worker uses the production repository and has no network access.
- `scan_legacy_data(*, repair=False)` is keyword-only, read-only (`PRAGMA query_only=ON` for the scan, OFF afterwards) and returns a `LegacyScanReport` (`scanned_rows`, `issues`, `counts()`, `flagged_keys()`); findings carry fixed text, never stored values. `repair` is refused for any value other than `False`.
- The Stage-2 legacy test constructed `CandleRepository(tmp_path/"legacy.db")` with a path instead of an engine and asserted findings on an empty database (self-contradictory). It was replaced, keeping the bound name `test_legacy_scan_flags_without_repair`, by a crafted legacy database.
- `delete_candles(keys, *, confirm: bool = False)` is the explicit manual-remediation step: it refuses unless the caller passes `confirm=True` (default `False`), then deletes in one transaction with validated keys; no automatic path calls it.
- Stored values of the wrong type (text/float/bytes/NULL, hostile identifiers) produce one fixed `MALFORMED_FIELD` finding per row; the scan never raises and never echoes stored values.
- Concurrency evidence: `tests/fixtures/process_runner.py` archives a JSON record per scenario; `tools/concurrency_evidence.py` repeats the suite and archives logs, JUnit and a summary; CI uploads them as the `concurrency-evidence` artifact.
- The concurrency evidence gate recomputes overlap from the raw worker windows (it never trusts the recorded `max_concurrency`), requires every expected multi-worker scenario by name and worker count, and fails closed on missing, malformed or non-overlapping evidence, failing exit codes, non-unique rows or a non-`ok` integrity check. Overlap is a per-record requirement; windows are measured from barrier release to insert completion, so a pathologically slow worker start could in principle fail the gate, which is the intended fail-closed behaviour (the gate is run 3 times and every run must pass).
