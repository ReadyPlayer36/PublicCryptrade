## Honest notes
- **Review fix (row_count on failure, boundary corrected):** a failure row records the count of rows that were fetched AND fully verified (client checks plus the service's own conversion). It is 0 for any failure before verification completes, including rows that came back but could not be converted (these now raise `DataValidationError` with code `MALFORMED_ROW`, no cause/context and no row values), and the real count for later failures (hashing, conflict, failure after the write began). Regression tests: `test_row_count_is_zero_before_verification_and_positive_after`, `test_failure_after_rows_were_fetched_and_verified_records_that_row_count`, `test_failures_before_any_rows_were_returned_record_zero_rows`.
- **Equivalent mutant (accepted):** removing the explicit `connection.rollback()` changes nothing observable, because closing a SQLAlchemy connection with an open transaction rolls it back and emits the same events. The tests therefore prove what matters operationally: a ROLLBACK statement is executed before the failure-audit transaction begins, and no candle data survives.
- **Tripwire exemption:** `src/trading_app/data/audit.py` contains a denylist of secret-like words, so the tripwire exempts string findings (only) for that one file; this is explicit, printed in the tripwire summary and pinned by a test. HTTP-method findings are still enforced there.
- **Not in D2a:** two-process concurrency tests, the legacy-data scan (D2b); CLI and the verification queries (D3). Allowlisted placeholders remaining are listed in `tests/hollow_allowlist.txt`.
