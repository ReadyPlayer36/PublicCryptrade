## Review fixes after the first D2b review
- **Malformed stored types (LEGACY-01):** `_scan_row` now checks the type of every integer/timestamp/identifier field (`id`, `open_time_ms`, `close_time_ms`, `trade_count`, `created_at_ms`, `symbol`, `timeframe`). A wrong type (text, float, bytes, NULL, a hostile identifier) yields exactly ONE fixed finding `MALFORMED_FIELD` per row; the other checks still run on the well-typed fields, so a malformed field never hides another finding. Findings carry fixed text only; identifiers that are not plain symbols/timeframes are shown as `<invalid>` (and kept out of the delete list; `row_id` is the handle for manual inspection). A last-resort handler guarantees a hostile row cannot crash the scan or leak through an exception message. Tests: `test_malformed_stored_types_get_one_fixed_finding_and_never_leak_values`, `test_a_malformed_field_never_hides_the_other_findings_on_the_same_row`, `test_a_hostile_row_object_cannot_crash_the_scan_or_leak_through_an_exception`, `test_well_formed_rows_are_unaffected_by_the_type_checks`; 9 of 9 mutations killed.
- **Strict concurrency evidence gate (TX-01, second review round):** `tools/concurrency_evidence.py` no longer trusts what a record claims. In every run it requires: pytest exit 0 and every worker exit 0; each expected multi-worker scenario (built-in manifest `EXPECTED_SCENARIOS`, one entry per real test, pinned to the real suite by a test) recorded with the expected worker count; for every multi-worker record, well-formed timing for every worker (finite, positive, not boolean, finish not before start, process id present), a recorded `max_concurrency` equal to the value RECOMPUTED from the raw windows, real temporal overlap (>= 2 at once; touching windows do not count) and no worker that overlapped no other; unique rows (`rows == distinct_keys`) and `integrity_check == ok`. Missing, malformed or absent scenarios, timing or overlap exit 1 (fail closed); a custom `--target` needs `--expect LABEL:N` or an explicit `--allow-no-expectations` (overlap and integrity are still verified); unexpected multi-worker scenarios also fail. `--verify-only DIR` applies the same checks to an existing evidence directory, which CI uses on the main test run's evidence, in addition to the 3-run stability step. Tests: 46 in `tests/tools/test_concurrency_evidence.py` including a run of the real suite through the strict gate (4 multi-worker scenarios, every one overlapping); 17 of 17 mutations of the new rules are killed.
- **Concurrency evidence archive (TX-01):** every `run_workers` scenario archives a JSON record (environment, parameters, per-worker result, exit code, timings and stderr tail with paths scrubbed, `max_concurrency`, final database rows/distinct keys/integrity check). `tools/concurrency_evidence.py --runs N` repeats the suite, archives `pytest-output.txt`, `junit.xml` and the evidence for every run plus `summary.json`, and fails closed (a failing run, no evidence, unreadable evidence or an integrity check that is not `ok`). CI runs it with 3 repetitions after the main test step and uploads `concurrency-evidence`. Observed here: every multi-worker scenario showed overlapping execution windows (max_concurrency equal to the worker count) even on a 1-CPU machine; single-worker setup steps show 1 as expected. Tests: `tests/tools/test_concurrency_evidence.py` (10 tests; 7 of 8 mutations killed on the first pass, the survivor (path scrubbing was never exercised) now has a direct test).

## Heuristics, stated plainly
- `FORMING_CANDLE` is a HEURISTIC: a row whose `created_at_ms` is at or before its `close_time_ms` was stored before the candle could be final. It can false-positive if the writer's clock was wrong and can miss forming candles stored later with a skewed clock. It never repairs; a human decides.
- The other codes (`MISALIGNED_OPEN`, `BAD_DURATION`, `INVALID_OHLC`, `NONPOSITIVE_PRICE`, `NEGATIVE_VOLUME`, `NEGATIVE_TRADE_COUNT`, `BAD_DECIMAL_TEXT`, `UNKNOWN_TIMEFRAME`, `SERIES_GAP`) are deterministic checks on stored values.

## Honest notes
- One mutant (commit instead of rollback on a conflict) survives the concurrency tests because a conflict is detected before any row is written, so there is nothing to commit; it is killed by the injected-failure repository tests from D1c.
- `delete_candles(keys, *, confirm: bool = False)` is a manual-remediation helper only: deletion needs an explicit opt-in (`confirm=True`, default `False`); no automatic path calls it and it never touches `data_fetches`. A test pins the signature (keyword-only, default `False`).
- The tripwire correctly flagged an ambiguous `.delete` attribute in `repository.py`; the code now uses SQLAlchemy's `delete()` function instead of weakening the scanner.
